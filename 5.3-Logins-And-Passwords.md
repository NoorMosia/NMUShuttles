# 5 TECHNICAL REQUIREMENTS

## 5.3 Logins & Passwords

This section lists the credentials used to access each role of the NMU Shuttle Management Network in the development/testing environment. There are three roles with two distinct authentication methods: **Admins** sign in with email + password, while **Students** and **Marshals** sign in with a one-time PIN (OTP) delivered to their university email.

> **Security note:** All credentials below are fictitious seed data for development and testing only. Admin passwords are seeded in plain text for convenience but are stored as **BCrypt hashes (cost factor 12)** in the database. Student and Marshal accounts have no stored password — access is granted via OTP at login time.

### 5.3.5 OTP Login Flow (Students & Marshals)

1. Enter university email on the mobile app login screen.
2. The API generates a **5-digit OTP**, stores it hashed, and sends it via the Resend email service.
3. Enter the code within **5 minutes** (configurable via `OTP_EXPIRY_MINUTES`).
4. On success, the API issues a **JWT** carrying the role claim (Student or Marshal), valid for 24 hours.
5. OTP endpoints are rate-limited to **5 requests per minute per IP**.

> In local development without a Resend API key configured, the OTP is not emailed — retrieve it from the API logs or database to complete login.
